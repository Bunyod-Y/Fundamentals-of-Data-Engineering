# L07 — Lakeflow Declarative Pipelines I: medallion, streaming tables, MVs, expectations

Exam: Pro S1, S3 (expectations/quarantine), S4 (event log). Warm-up: COPY INTO; Auto Loader;
_rescued_data.
Special: pipeline code cannot run in a normal notebook cell. Create pipeline source files (SQL and
Python, current pyspark.pipelines API; mention legacy `import dlt`) and a serverless pipeline with
the CLI/SDK, run it, and verify through tables and event_log() from the solved notebook.
Concepts: declarative vs imperative; flows/datasets; streaming table vs MV vs temporary view;
SQL and Python syntax; expectations (warn, DROP ROW, FAIL UPDATE); quarantine; triggered vs
continuous; dev vs prod mode; refresh vs full refresh; incremental MV refresh; event log metrics;
Structured Streaming vs Declarative Pipelines choice.
Examples: bronze → silver → gold MV; event log expectation counts; new batch → streaming table
processes only new files; source update → streaming table vs MV behaviour; quarantine table;
FAIL UPDATE in event log; full refresh effect; Python version of silver.
Practice: P1 expectation blanks; P2 missing STREAM, wrong ON VIOLATION; P3 gold MV + quarantine;
P4 blind: silver layer in Python.

## Design (built 2026-10-22)

- One learner notebook; no helper notebooks. The notebook writes the pipeline source files (`bronze.sql`, `silver.sql`,
  `gold.sql`, later `silver_py.py`) to `/Users/<me>/_lesson_runtime/L07` with `w.workspace.upload`, creates serverless,
  triggered pipelines through the Pipelines REST API (`w.api_client.do`), starts updates (normal, full refresh,
  `validate_only`), waits, and reads tables plus `event_log('<id>')`. Setup and Cleanup delete every pipeline named
  `dbacademy_l07*` and the runtime folder.
- Main pipeline `dbacademy_l07_claims`: E1 first update, E3 new file, E4 provider change, E7 full refresh, E8 adds the
  Python silver file. E6 uses `dbacademy_l07_checks` (FAIL UPDATE, then a dry run of a streaming table without STREAM)
  and deletes it. Practice tasks share `dbacademy_l07_practice` (libraries replaced per task, always full refresh).

## Evidence from test runs (outside _authoring/L07.json)

- Run 685327198736832 (job, serverless): the preinstalled SDK is 0.40.0; `w.pipelines.create(..., root_path=...)` failed
  with `TypeError: PipelinesAPI.create() got an unexpected keyword argument 'root_path'` -> the lesson uses REST.
- Local SDK probes (2026-10-22, profile DEFAULT): with two pipelines of this lesson in the workspace (both IDLE), a third
  pipeline's update failed in ~6 s with `DeploymentException ... RESOURCE_EXHAUSTED: You've hit the limit for severless
  compute for free usage`; the event log of that pipeline was not available (`EVENT_LOG_UNAVAILABLE`) and the error was
  only in the events API. After deleting one pipeline the third one ran. Free Edition docs: "One active pipeline per
  pipeline type". Design consequence: never more than two lesson pipelines at once.
- Local probes: `CREATE STREAMING TABLE ... AS SELECT * FROM read_files(...)` (no STREAM) -> dry run FAILED with
  `CREATE_APPEND_ONCE_FLOW_FROM_BATCH_QUERY_NOT_ALLOWED`; deleting a pipeline without cascade keeps its tables.
- Run 964408990712712: first complete run, SUCCESS in 679 s. Final verification (`--twice`): runs 253741004914573 and
  528136365562026, SUCCESS in 644 s and 618 s, METRICS identical (nd. keys ignored).

## Not verifiable here (concept only)

  `refresh_selection`, `pipelines.reset.allowed`; the Lakeflow Pipelines Editor UI.
