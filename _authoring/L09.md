# L09 — Lakeflow Jobs: tasks, parameters, control flow, repair

Exam: Pro S1, S4, S8. Warm-up: SCD1 vs SCD2; MERGE upsert; sequence-by purpose.
Special: create task notebooks in "Databricks - Learning/L09_tasks", create/run jobs with the
Databricks SDK from the notebook, poll runs, delete jobs in Cleanup; CLI equivalents as text.
Concepts: task types (notebook, script, SQL, pipeline, run job, If/else, For each); dependencies and
run-if; job vs task parameters; dynamic value references; task values; triggers (schedule, file
arrival, table update, continuous); retries/timeouts/concurrency; notifications; serverless
environments, dependencies, performance mode; repair run; run with overrides; API/CLI/SDK.
Examples: 3-task job; task values; If/Else on row count; For Each over practices; forced failure +
repair; parameter override; run history and durations via SDK; job JSON export.
Practice: P1 job definition blanks; P2 wrong depends_on, wrong dynamic reference; P3 For Each job with
notifications; P4 blind: create, run, fail, repair with SDK.

## Design (built 2026-10-26)

- One learner notebook; no helper notebooks in git. The lesson writes its task code at run time to
  `/Users/<me>/_lesson_runtime/L09` (seven SOURCE notebooks via `POST /api/2.0/workspace/import`, one plain `.py` file via
  `w.workspace.upload(..., ImportFormat.AUTO)`), creates jobs with the Jobs REST API 2.2 (`w.api_client.do`), runs them with
  `run-now`, polls `runs/get` every 10 s, reads `runs/get-output`, repairs with `runs/repair`, and deletes every
  `dbacademy_l09*` job, the runtime folder and the schema in Cleanup (setup does the same first).
- Compute budget: job `dbacademy_l09_daily_encounters` (ingest notebook → If/else → build_summary notebook → For each over
  the practices task value, concurrency 2 / false branch: Python script with `environment_version` 4) runs twice (run 1
  default `run_date`, run 2 overridden to an empty day); job `dbacademy_l09_lab_repair` runs once, fails
  (`TABLE_OR_VIEW_NOT_FOUND`), and is repaired; P4 runs one more job + one repair with new `job_parameters`. P1–P3 only
  create jobs (validated with `jobs/get`), E7 only creates definitions (mistakes, paused file-arrival / table-update triggers).
  Per lesson run: 4 job runs + 2 repairs = 14 task runs with code (run 1: 5, run 2: 2, E5: 2 + repair 2, P4: 1 + repair 2); at most 3 job tasks at the same time. Every task sets
  `disable_auto_optimization: true`, `max_retries: 0`; jobs set `performance_target: PERFORMANCE_OPTIMIZED`.
- Deviation from the spec: the spec's "L09_tasks" folder became runtime files (one notebook per lesson rule); examples are
  numbered E1–E7 (task values E2, For each E3, If/else + override E4, failure + repair E5, history E6, export E7).
- Build tool change: `build_notebook.py` shows a SOLUTION block that contains `{{` (job dynamic value references) as an HTML
  `<pre>` block with the braces as entities, because a fenced block in markdown would be read as placeholders. Markdown text
  writes references as `<code>&#123;&#123;…&#125;&#125;</code>` for the same reason.
